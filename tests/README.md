# Channels module: end-to-end tests

Cypress tests of the channels module, run against a Jahia started in Docker. Jahia runs in a container, Cypress runs
on the host.

## Prerequisites

- Docker with `docker-compose`, Node.js and Yarn 1 (`yarn install` in this folder).
- A Jahia license for the image (`jahia/jahia-ee`), passed base64-encoded in `JAHIA_LICENSE`, or in
  `/tmp/license.xml`. Never commit it.
- The module built: `mvn clean install` at the root of the repository.

The defaults (Jahia version, image, port 8090, root password of the test instance) are in `harness.env`. Override
them in your shell or in `tests/.env` (gitignored).

## Commands

```bash
./ci.build.sh                                   # copies ../target/channels-*-SNAPSHOT.jar to ./artifacts
JAHIA_LICENSE=$(base64 -i license.xml) ./ci.startup.sh notests   # starts Jahia (container channels-jahia)
./env.run.sh                                    # provisions Jahia, installs ./artifacts, runs all the specs
./env.run.sh --spec cypress/e2e/05-live-device-resolution.cy.ts  # one spec
./env.debug.sh                                  # interactive Cypress runner
./env.down.sh                                   # stops the container and removes its volumes
```

`env.run.sh` installs the jar of `./artifacts` each time (`installOrUpgradeBundle`, forced), so run
`./ci.build.sh` after each build of the module. Results go to `results/` (mochawesome report, JUnit XML,
screenshots, videos).

## Specs

| Spec | What it covers |
| --- | --- |
| `01-channels-api` | Module started; the channel list of `jcontent.channels` (generic plus the shipped devices); visibility; display names and frame sizes of the variants; viewports ordered by width; frame pictures served. |
| `02-runtime-configuration` | A device added by an `installConfiguration` (.cfg file) or `editConfiguration`, changed and removed without restart. |
| `03-live-user-agent-filter` | Live: include and exclude modes for the iPhone; iPad and Android phone behave like desktop for these rules; HTML cache per channel. Creates the site `channelstest`, used by 04. |
| `04-jcontent-customized-preview` | jContent customized preview: "Mobile 360" portrait, framed by the module, with a 360x800 screen; content of the device selector. |
| `05-live-device-resolution` | Live: each User-Agent device (iPhone, Android phone, iPad, Android tablet) resolves its own channel, desktop none; the `generic_mobile` fallback of the two phones; a viewport is never resolved; a device added at runtime with a `userAgentPattern` is resolved, then no longer once deleted; two devices matching the same User-Agent: the first identifier in alphabetical order wins. |
| `06-provider-configuration` | Invalid configurations (no `identifier`, invalid `userAgentPattern`) ignored and logged; duplicate identifier listed once; defaults of `fallBack` and `visible`; custom capabilities; `userAgentPattern`, `fallBack` and `template-type-mapping` of the shipped User-Agent devices; stopping the bundle removes its channels, starting it restores them. |
| `07-exclusion-filter` | Selections of several channels; the mixin without selection; preview with `?channel=` (device and viewport); the parameter ignored in live; edit mode: the `unselectedChannel` wrapper and its "Unselected from this channel" overlay in `/cms/editframe` and in the jContent page builder, and removal when another channel is previewed. |
| `08-preview-frames` | The frame page generated by the module (`ChannelPreviewFrameFilter`) for every device and variant of `devices.json`: frame picture and size, screen size and exact position (`decorator-screen-positions`, also checked against `screenX`/`screenY` and against the screen of the SVG picture), `data-overlay-scrollbars`, address of the screen (`noembed=true`); `lang`, `main`, screen `title` and `tabindex`; cache-busting `?v=` of the CSS and JS; other request parameters kept and encoded, first variant by default; malformed frame configurations (message and log); devices without frame or with an incomplete frame. |
| `09-jcontent-preview-devices` | jContent customized preview: order of the device selector; Mobile 360 landscape, iPhone, Android phone, iPad landscape, Laptop 1280, Desktop 1920 with a page higher than the screen: no scrollbar around the device, width of the previewed page (overlay-scrollbar style present for phones and tablets, absent for laptop and monitor), no border on the jContent iframe, accessibility attributes and focus not moved; a device without frame, at `decorator-image-sizes` + 16px. Writes the kind of scrollbars of the test browser to `results/scrollbars.txt`. |
| `10-content-editor` | Content Editor (advanced options, Visibility): the channel option lists the channels and saving sets `j:channelSelection` / `j:channelIncludeOrExclude`; the `viewChannelsTab` permission imported by the module; a user without it does not get the option (UI and form definition). The UI tests need jContent before 3.7.0 (3.5.0 in Jahia 8.2.3.2): from 3.7.0, nothing renders the channel option of Content Editor (jContent commit c52136df), and the spec skips them. |
| `11-packaging` | The `jmix:channelSelection` mixin as registered; the installed bundle has no Spring entry or extender, its Declarative Services components (provider, exclusion filter, preview frame filter, channel resolution filter) are active; `Jahia-Required-Version`. |
| `12-limits` | Limits: a `variant` that the device does not declare is rejected in preview; only the first 1024 characters of the User-Agent are matched; a device cannot fall back to itself; a cookie only selects a declared channel, and the page is cached for each channel; a `channel` parameter that names no declared channel means the generic channel. |
| `99-teardown` | Deletes the site `channelstest`. |

The specs 05 and later create and delete their own site, and remove the device configurations they create (they
carry the property `cypress.test = true`, which the module ignores). They can run alone or in any order. 04 needs
the site of 03.

Values that GraphQL does not expose (fallBack, capabilities, log lines, bundle headers) are read with groovy scripts
(`cypress/fixtures/groovy`) run through the provisioning API; they return JSON with `setResult`.

Not covered: device-specific views (`template-type-mapping`), which would need a module with `html-<type>` views.
Only the values of the capability are checked (06).

Scrollbars: the frame page hides the scrollbar of the previewed page for the devices with `overlay-scrollbars`. The
width checks of 09 only prove something in a browser with classic (space-taking) scrollbars; the Electron browser of
Cypress on macOS uses them (see `results/scrollbars.txt` after a run).

## devices.json

`cypress/fixtures/devices.json` lists the shipped devices that have a frame, with `overlayScrollbars` and, per
variant, the screen size, the frame size and the screen position (`screenX`, `screenY`). It is generated, with the device configurations and the frame pictures, by `tools/generate-devices.py` (run
from the root of the repository). Do not edit it by hand: change the tables of the script and run it again.
